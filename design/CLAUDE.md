# Forge — Design Source of Truth

> This folder is the **design source** for the Forge AI Store Builder product.
> It is maintained in a separate design tool by the design team and synced to this repo.
> **Read this file first** before making changes that touch UI, copy, layout, color, or component structure.

## Golden rules for Claude Code

1. **Treat `design/` as the spec.** When implementing a feature in the real app, mirror the structure, naming, copy, and visual language from `design/` — don't invent new patterns when one already exists here.
2. **Don't edit files in `design/` directly.** They are regenerated by the design tool. Any edits you make here will be overwritten on the next sync. If you find a bug in the design, file an issue with the `design` label instead.
3. **Read `design.lock.json`** before adding new tokens. If a color, spacing value, or radius already exists, **reuse it**. Never hardcode hex codes or magic numbers in the implementation.
4. **Read `CHANGELOG.md`** at the start of every session. It tells you what changed since you last looked, so you can propagate the diff to the live app.
5. **When the design changes, the implementation follows.** If `design/CHANGELOG.md` shows a new version, treat propagating those changes as a P0 task.

## Update protocol — when the design changes

When `design/CHANGELOG.md` adds a new entry:

1. **Read the diff.** `git diff HEAD~1 -- design/` shows exactly what changed.
2. **Check `design.lock.json`** for token changes. If `tokens.version` bumped, re-read tokens and propagate to the implementation's CSS / theme module.
3. **Map design files → implementation files.** The mapping is:
   - `design/styles.css` → `apps/admin/src/styles/global.css` (or your equivalent)
   - `design/*.jsx` → `apps/admin/src/components/<module>/`
   - `design/landing.html` → `apps/marketing/pages/index.tsx`
4. **Preserve implementation logic.** The design files are static mocks; the real app has data fetching, state management, and routing. Apply visual / structural changes only — don't blindly copy mock data or hardcoded states.
5. **Run the design parity check** (if set up): `pnpm design:check` compares live tokens to `design.lock.json` and fails CI on drift.
6. **Update `IMPLEMENTATION_NOTES.md`** in this folder if you needed to deviate (e.g. "design uses a static `<select>`, impl uses Radix Select for a11y").

## Conventions

- **Naming:** kebab-case for CSS classes, PascalCase for React components, camelCase for props.
- **Copy:** sentence case for buttons and labels, no terminal punctuation on labels.
- **Iconography:** stroked 1.5px line icons, 16×16 viewBox, sized 14–20px. Inline SVG only — no icon font, no library.
- **Spacing:** 4px base unit. Common values: 4, 6, 8, 10, 12, 14, 16, 20, 22, 24.
- **Empty states:** every list/grid has one. Centered icon (40–56px), 18px title, 13px gray sub, primary action.
- **Loading:** prefer optimistic UI + `.loader-dot` over spinners. Keep skeletons off unless > 600ms.

## Don't

- Don't add new top-level color tokens without updating `design.lock.json` and `CLAUDE.md`.
- Don't import additional UI libraries (Material, Chakra, Bootstrap). The design is unstyled-react-by-design — bring your own primitives that match these tokens.
- Don't restyle `.panel`, `.btn`, `.status-pill`, etc. with overrides — extend or compose.
- Don't change copy without checking the design doesn't have a specific tone/voice intent.
