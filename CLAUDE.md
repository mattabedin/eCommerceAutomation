# Forge — Claude Code working agreement

This repo is the home of the Forge AI Store Builder. The `design/` folder is the **single source of truth** for visual + UX design — read `design/CLAUDE.md` before touching anything UI-related.

## Team (subagents)

Four specialized subagents live in `.claude/agents/`. Use them via the `Agent` tool with `subagent_type` set to the agent's `name`.

| Agent | Use for |
| --- | --- |
| `designer` | Token lookups, component lookups, design diff propagation, copy/tone, parity reviews. Connected to the `design/` source of truth. |
| `frontend-developer` | React/TSX/CSS in `apps/admin/` and `apps/marketing/`. Mirrors `design/` into the live app. |
| `backend-developer` | Server tier: API routes, DB schema, auth, jobs, multi-tenancy, billing logic. |
| `api-integration` | All third-party APIs: Stripe, DNS/domains, storage/CDN, email/SMS, Anthropic Claude, analytics. Owns credentials, retries, webhooks. |

## Routing rules

- UI work → `frontend-developer` (consults `designer` first if visual).
- New endpoint, schema change, or auth/billing logic → `backend-developer`.
- Outbound call to any third party → `api-integration`. Backend never calls SDKs directly.
- "What does this look like / what token / what copy?" → `designer`.
- Design version bumped in `design/CHANGELOG.md` → `designer` produces a propagation spec, hands it to `frontend-developer`.

## Hard rules

- Never edit files inside `design/` — they are regenerated by the design tool.
- Never hardcode hex codes, magic spacing, or radii in implementation code — use tokens from `design/design.lock.json`.
- Never put third-party SDK calls in route handlers or React components — go through `packages/integrations/<provider>/`.
- Never commit secrets. All credentials live in env vars, documented in `.env.example`.
